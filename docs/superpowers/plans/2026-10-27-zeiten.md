# Zeiten im Blick (Baustein 5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Je Schritt des Ablaufs und je Agent-Frage ist die Dauer über die letzten 50 Läufe sichtbar, mit Zielwerten, die rot werden, damit Beschleunigung messbar wird.

**Architecture:** Reine Kennzahlen-Berechnung in `app/ablauf/zeiten.py` aus `runs.steps` (Zeitstempel je Schritt, neu: Dauer je Frage in Schritt 6). Ein lesender Endpunkt `GET /api/runs/zeiten` über die letzten 50 Läufe des Workspaces. Auf `/ablauf` ein Abschnitt „Zeiten“ als Tabelle, rote Zelle bei Zielüberschreitung, Link zur Langfuse-Session des langsamsten Laufs.

**Tech Stack:** FastAPI, SQLAlchemy 2, Next.js 16, Vitest, Playwright. Keine neuen Abhängigkeiten.

**Spec:** `docs/superpowers/specs/2026-10-26-ablauf-wissen-vergleich-design.md`, Abschnitt „Baustein 5: Zeiten im Blick“.

## Global Constraints

- Repo-Regeln `AGENTS.md`, `frontend/AGENTS.md` (Next.js 16: `node_modules/next/dist/docs/` lesen). Ponytail: nichts bauen, was die Spec nicht nennt; keine Diagramme in v1.
- Zielwerte genau so (Sekunden): `lesen` ≤ 60 je Dokument, `zusammenfassung` ≤ 30 je Frage, `gesamt` ≤ 180 je Lauf. Andere Schritte ohne Ziel (`ziel = None`).
- Kennzahlen je Schritt-Key über die letzten 50 Läufe des Workspaces (neueste zuerst): `anzahl`, `mittel_s`, `median_s`, `max_s`, `letzter_s`, `ziel_s`, `ueber_ziel` (bool, bezogen auf `letzter_s`), `langsamster_run_id`. Nur Schritte mit `started_at` und `finished_at` zählen; fehlende Werte sind `None`, nie 0.
- Dauer je Frage: Schritt 6 schreibt je Antwort `dauer_s` (gerundet auf 0,1 s) in `steps[zusammenfassung].result[*]`.
- Farben nur über Tokens (`text-error` bzw. `bg-error-soft` für rote Zellen). Barrierefreiheit: Tabelle mit `<caption>`, `scope="col"`, rote Zelle zusätzlich mit Text „über Ziel“ im `aria-label`.
- Öffentliche Texte: keine Kosten, keine Projekt-IDs, keine Zitate.
- Vor dem Push: `ruff check .`, Backend-Suite (`python -m pytest -q`), `npm run lint`, `npx tsc --noEmit`, `npx vitest run`, `npx playwright test e2e/ablauf.spec.ts`.
- Commits mit `Part of SIN-<neu>` (Issue wird in Task 4 angelegt; bis dahin `SIN-1103`) und `Co-Authored-By: <Modell> <noreply@anthropic.com>`.

## Review Focus

1. Ein Lauf mit Schritt auf `fehler` (ohne `finished_at` bei späteren Schritten) darf die Kennzahlen nicht verfälschen: nur abgeschlossene Schritte zählen, `anzahl` sinkt entsprechend (Task 1 Test).
2. Noch kein Lauf im Workspace: Endpunkt liefert leere Schritte mit `anzahl = 0`, Seite zeigt „Noch keine Läufe“ statt leerer Tabelle (Task 1 + Task 3 Tests).
3. Route-Reihenfolge: `GET /api/runs/zeiten` muss vor `GET /api/runs/{run_id}` registriert sein, sonst 404 „Lauf nicht gefunden“ (Task 2 Test ruft genau diese URL).
4. Ein sehr langsamer Lauf (Erst-Download der Embeddings) dominiert `max_s`, nicht `mittel_s`: Median ist Pflicht in der Tabelle (Task 3 zeigt Median statt Mittel als Hauptwert).
5. `langsamster_run_id` muss zum selben Workspace gehören; der Langfuse-Link kommt aus `Run.trace_url` dieses Laufs, `null` ohne Tracing (Task 2 Test).

```python
from app.ablauf.schritte import SCHRITTE, beende, neue_schritte, starte
from app.ablauf.zeiten import ZIELE, kennzahlen

def _lauf(run_id, dauern: dict[str, float], fragen: list[float] | None = None, trace_url=None):
    steps = neue_schritte(); t = 0.0
    for key, _ in SCHRITTE:
        if key not in dauern: continue
        a = f"2026-10-27T10:00:{t:06.3f}+00:00"; t += dauern[key]; b = f"2026-10-27T10:00:{t:06.3f}+00:00"
        steps = beende(starte(steps, key, a, ""), key, b, "")
    if fragen is not None:
        steps = [{**s, "result": [{"question": "q", "answer_md": "a", "sources": [], "dauer_s": d} for d in fragen]} if s["key"] == "zusammenfassung" else s for s in steps]
    return {"id": run_id, "steps": steps, "trace_url": trace_url, "created_at": "2026-10-27T10:00:00+00:00"}

def test_leer():
    k = kennzahlen([])
    assert k["laeufe"] == 0 and k["schritte"]["lesen"]["anzahl"] == 0 and k["schritte"]["lesen"]["mittel_s"] is None

def test_mittel_median_max_letzter_und_ziel():
    k = kennzahlen([_lauf("neu", {"lesen": 10}), _lauf("alt", {"lesen": 70}), _lauf("uralt", {"lesen": 20})])
    s = k["schritte"]["lesen"]
    assert s["anzahl"] == 3 and s["mittel_s"] == 33.3 and s["median_s"] == 20.0 and s["max_s"] == 70.0
    assert s["letzter_s"] == 10.0 and s["ziel_s"] == 60.0 and s["ueber_ziel"] is False and s["langsamster_run_id"] == "alt"

def test_ueber_ziel_bezieht_sich_auf_letzten():
    assert kennzahlen([_lauf("a", {"lesen": 61})])["schritte"]["lesen"]["ueber_ziel"] is True
    assert kennzahlen([_lauf("a", {"maschine": 500})])["schritte"]["maschine"]["ziel_s"] is None

def test_nur_abgeschlossene_schritte_zaehlen():
    lauf = _lauf("a", {"lesen": 5}); lauf["steps"] = starte(lauf["steps"], "maschine", "2026-10-27T10:00:30+00:00", "")
    assert kennzahlen([lauf])["schritte"]["maschine"]["anzahl"] == 0

def test_gesamt_und_fragen():
    k = kennzahlen([_lauf("a", {"lesen": 100, "zusammenfassung": 50}, fragen=[10.0, 40.0])])
    assert k["gesamt"]["letzter_s"] == 150.0 and k["gesamt"]["ueber_ziel"] is False
    assert k["fragen"]["anzahl"] == 2 and k["fragen"]["max_s"] == 40.0 and k["fragen"]["ueber_ziel"] is True
```
