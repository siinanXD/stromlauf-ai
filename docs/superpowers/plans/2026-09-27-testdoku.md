# Testwerk Teil 4: Test-Dokumentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Datengetriebener Doku-Generator und zwei vollständige, in sich stimmige Dokumentensätze (UR-01 Umroller, PM1-AR Aufrollung), im Testwerk verknüpft.

**Architecture:** `scripts/testdoku/` (model, render_pdf, render_rest, machines/*, build) mit reportlab/openpyxl aus dem `examples`-Extra; Tests im Backend lesen die erzeugten Dateien mit den vorhandenen Parsern (pdf_layout, signal_graph, onboarding, diagnosis); Lader-Erweiterung `--docs`.

**Spec:** `docs/superpowers/specs/2026-09-27-testdoku-design.md`

## Global Constraints

- Kein LLM-/Vision-Aufruf (Upload mit `vision=false`). Alles frei erfunden, keine Herstellernamen.
- Kennzeichen nach IEC 81346 wie FB-01 (`-M1`, `-X3:5`, `E0.0`, `A4.0`); Blattverweise `/Blatt.Spalte` nur, wenn das Kennzeichen dort steht.
- FB-01-Generator und -Dateien bleiben unverändert.

## Review Focus

1. Verweis auf ein Blatt, auf dem das Kennzeichen zweimal in verschiedenen Spalten steht: Verweis zeigt auf das Symbol, nicht die Erwähnung.
2. AWL-Parser: FB mit >10 Netzwerken, Schrittkette mit Merkern, CALL mit Parametern über zwei Baugruppen (EB0/EB1) → Signalgraph bindet richtig.
3. Onboarding-Parser: Fehlertabelle mit Verweisen wie „/7.3“ und mehreren BMK je Zeile.
4. Lader zweimal ohne `--refresh`: keine doppelten Quellen, keine doppelten Fehler.
5. Maschinen ohne passende Halle (fremde DB): Lader meldet, statt abzubrechen.
