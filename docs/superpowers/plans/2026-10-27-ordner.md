# Ordner-Upload mit Maschinenerkennung (Baustein 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein ganzer Ordner (auch verschachtelt, auch gemischt) wird auf `/ablauf` abgelegt; das System bündelt die Dateien zu Anlagen, zeigt den Vorschlag, der Mensch bestätigt oder sortiert um, und je Anlage läuft der bekannte Ablauf aus Baustein 1.

**Architecture:** Die Gruppierung ist eine reine Funktion im Backend (`app/ablauf/gruppieren.py`), über `POST /api/runs/gruppen` erreichbar (nur Namen und relative Pfade, keine Dateien). Der Browser schickt nach der Bestätigung je Gruppe einen normalen `POST /api/runs`; die Dateien bleiben bis dahin im Browser. Es entsteht keine neue Tabelle und kein Zwischenspeicher. Die Seite zeigt je Lauf eine Graph-Reihe und fragt alle Läufe gemeinsam ab.

**Tech Stack:** FastAPI, Next.js 16, React Flow (vorhanden), Vitest, Playwright. Keine neuen Abhängigkeiten.

**Spec:** `docs/superpowers/specs/2026-10-26-ablauf-wissen-vergleich-design.md`, Abschnitt „Baustein 4: Ordner-Upload mit Maschinenerkennung“.

## Global Constraints

- Repo-Regeln `AGENTS.md`, `frontend/AGENTS.md` (Next.js 16: `node_modules/next/dist/docs/` lesen). Ponytail: nichts bauen, was die Spec nicht nennt.
- Erkennung in drei Stufen, vom Sicheren zum Unsicheren: (1) Unterordner, (2) Kennung aus Dateiname und Schriftfeld, (3) Ähnlichkeit mit Nachfrage. **Abweichung dieses Plans:** Stufe 3 liefert in diesem PR keinen automatischen Vorschlag; Dateien ohne Ordner und ohne Kennung stehen als „unzugeordnet“ und werden vom Menschen zugewiesen (das ist die Nachfrage). Die Embedding-Ähnlichkeit folgt als eigenes Issue, Grund: sie braucht gelesene Dokumente, also eine zweite Phase nach dem Upload. Steht so in Spec-Abschnitt „Ausgelassen“ des PR.
- Kennungs-Muster (`KENNUNG`): ein Token aus 2–4 Großbuchstaben, optional Ziffer, Bindestrich, 1–3 Buchstaben/Ziffern, als letztes Token vor der Endung oder in Klammern: `FB-01`, `UR-01`, `PM1-AR`, `KL-7A`. Vergleich ohne Groß/Klein und ohne Bindestrich (`fb01 == FB-01`).
- Gruppenname = Ordnername (Stufe 1) bzw. Kennung (Stufe 2). Dateien direkt im Wurzelordner gehen in Stufe 2. Jede Gruppe trägt `quelle: "ordner" | "kennung"`, jede Datei behält ihren relativen Pfad.
- Grenzen: höchstens 200 Dateien und 500 MB je Ablage (Prüfung im Browser vor dem Vorschlag, klare Meldung), höchstens 100 Dateien je `POST /api/runs` (Backend, 400). Keine ZIP-Dateien, keine Erkennung über Bildinhalte.
- Halle „Ablauf“ wird im Endpunkt `create_run` idempotent angelegt (vor dem Thread), damit parallele Läufe keine zwei Hallen erzeugen.
- Alle bestehenden Tests und Belege aus Baustein 1 und 5 bleiben grün; `e2e/ablauf.spec.ts` wird erweitert, nicht ersetzt.
- Barrierefreiheit: Vorschlag als Liste mit Überschriften je Gruppe, Umsortieren per `<select>` je Datei (Tastatur), Ziele ≥ 44 px, kein Drag-only.
- Öffentliche Texte: keine Kosten, keine Projekt-IDs. Commits mit `Part of SIN-<neu>` (bis Task 5 `SIN-1103`) und `Co-Authored-By`.

## Review Focus

1. Zwei Dateien mit derselben Kennung in verschiedenen Unterordnern: Unterordner gewinnt, zwei Gruppen (Task 1 Test).
2. Ein Unterordner ohne erlaubte Dateien (nur `.zip`/`.exe`) erzeugt keine leere Gruppe; `README.md` und Fotos sind erlaubt und landen in der Gruppe ihres Ordners (Task 1 Test).
3. 201 Dateien oder 501 MB: Meldung vor dem Vorschlag, kein Request (Task 3 Test).
4. Zwei Läufe gleichzeitig: Ingestion-Lock serialisiert Schritt 2, beide werden `fertig`, genau eine Halle „Ablauf“ (Task 2 Test).
5. Nutzer sortiert alle Dateien einer Gruppe weg: Gruppe verschwindet, „Alle starten“ ignoriert leere Gruppen; eine Gruppe ohne Namen bekommt „Anlage N“ (Task 4 Vitest).

```python
from pathlib import Path
from app.ablauf.gruppieren import gruppiere, kennung_aus_name

EX = Path(__file__).resolve().parents[2] / "examples"

def _namen(ordner: str) -> list[str]:
    return sorted(p.name for p in (EX / ordner).iterdir() if p.is_file())

def test_kennung_aus_dateiname():
    assert kennung_aus_name("01_Stromlaufplan_FB-01.pdf") == "FB01"
    assert kennung_aus_name("04_SPS_Programm_PM1-AR.awl") == "PM1AR"
    assert kennung_aus_name("Betriebsanleitung.md") is None

def test_gemischter_ordner_ergibt_drei_gruppen():
    dateien = [{"name": n, "pfad": n} for o in ("foerderband", "umroller", "aufrollung") for n in _namen(o)]
    g = gruppiere(dateien)
    assert [x["name"] for x in g["gruppen"]] == ["FB-01", "PM1-AR", "UR-01"]
    assert all(x["quelle"] == "kennung" for x in g["gruppen"])
    assert sum(len(x["dateien"]) for x in g["gruppen"]) == 18 and g["unzugeordnet"] == []

def test_unterordner_gewinnt_vor_kennung():
    dateien = [{"name": "01_Stromlaufplan_FB-01.pdf", "pfad": "a/01_Stromlaufplan_FB-01.pdf"},
               {"name": "02_Stueckliste_FB-01.xlsx", "pfad": "b/02_Stueckliste_FB-01.xlsx"}]
    g = gruppiere(dateien)
    assert [(x["name"], x["quelle"]) for x in g["gruppen"]] == [("a", "ordner"), ("b", "ordner")]

def test_wurzeldateien_ohne_kennung_sind_unzugeordnet():
    g = gruppiere([{"name": "notizen.md", "pfad": "notizen.md"}, {"name": "archiv.zip", "pfad": "archiv.zip"}])
    assert g["gruppen"] == [] and g["unzugeordnet"] == ["notizen.md"] and g["ignoriert"] == ["archiv.zip"]

def test_ordner_nur_mit_ignorierten_dateien_ergibt_keine_gruppe():
    g = gruppiere([{"name": "setup.exe", "pfad": "x/setup.exe"}])
    assert g["gruppen"] == [] and g["ignoriert"] == ["x/setup.exe"]
```
