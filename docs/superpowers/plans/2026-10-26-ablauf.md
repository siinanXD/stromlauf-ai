# Ablauf (Baustein 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dateien hochladen, sieben Schritte laufen von selbst und werden auf `/ablauf` als React-Flow-Graph live grün, jeder Schritt hat einen Langfuse-Span, am Ende steht das Ergebnis.

**Architecture:** Eine Tabelle `runs` mit den Schritten als JSON; ein Orchestrator-Thread führt vorhandene Bausteine (Ingestion, Onboarding, Steckbrief, Modell, Agent) nacheinander aus und schreibt nach jedem Schritt. Die Seite fragt alle 2 s `GET /api/runs/{id}` und zeichnet den Graphen nur lesend.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, LangGraph, Langfuse Python SDK v3, Next.js 16, `@xyflow/react` 12, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-26-ablauf-wissen-vergleich-design.md`, Abschnitt „Baustein 1“.

## Review Focus

1. Upload ohne Datei oder mit nicht erlaubter Endung → 400/415 vor dem Anlegen einer Wissensquelle, keine leere Quelle bleibt zurück (Task 4).
2. Ingestion eines Dokuments schlägt fehl (z. B. Scan ohne Text) → Schritt „lesen“ wird `fehler` mit dem Dokumentfehler, Lauf `fehler`, Schritte 3–7 bleiben `wartet` (Task 1, Task 3).
3. Ollama nicht erreichbar → Schritt 6 `fehler` mit „Modell nicht erreichbar“, Ergebnis-Teile aus Schritt 4 und 5 bleiben sichtbar (Task 3, Task 6).
4. `GET /api/runs/{id}` aus fremdem Workspace → 404, nie Daten eines anderen Workspaces (Task 4).
5. Backend neu gestartet, während ein Lauf läuft → Lauf bleibt `laeuft` mit dem letzten Schritt auf `laeuft`; die Seite zeigt nach 10 Minuten ohne Fortschritt „Lauf hängt, Backend neu gestartet?“ statt endlos zu drehen (Task 6).
